## 1. 背景与目标

### 1.1 问题

养宠家庭记录分散（相册、备忘录、群聊）：喂食量靠记忆，多人喂养易重复/漏喂；驱虫疫苗靠脑子记经常超期；体检用药史无法回溯；便便性状、饮水量等异常信号没有被结构化沉淀。

### 1.2 产品定位

面向多猫/多狗家庭的**轻量照护记录工具**：3 秒记一笔，数据自动汇成健康时间线，**并基于记录生成健康建议**（健康简报四维解读 + AI 养护规划，见 8）。

### 1.3 成功指标 \[待确认，需与运营对齐]

| 指标           | 目标          |
| ------------ | ----------- |
| 记一笔完成耗时（含表单） | ≤ 15 秒      |
| 7 日留存        | ≥ 40%       |
| 人均记录条数       | ≥ 3 条/天（活跃） |
| 家庭空间渗透率      | ≥ 15%       |

## 2. Goals & Non-Goals

**Goals**

1. 19 种内置事项结构化录入 + 自定义分类（表单 schema 配置化）
2. 多宠物、猫/狗物种差异化（入口过滤 + 选项过滤）
3. 喂食营养量化：克数→kcal→RER 建议区间→今天该喂多少
4. 周期事项自动提醒（护理计划 + 待办闭环）
5. 家庭多人共享（直发邀请、对方接受后加入）+ 记录归属
6. AI 辅助：语音 / 拍药板 OCR / 估体况 / 这能吃吗 / AI 管家 / 健康简报
7. 会员订阅（¥9.9/月，调研定价）

**Non-Goals**

1. 不做社区/内容流；2. 不做电商带货（速记只给结论）；3. 不做问诊撮合/挂号；4. 不做硬件对接；5. 首发不做原生 App；6. 首发不做多语言；7. 不做按宠物单独授权的家庭模型（绑定用户级，决策 #12），

   ；8. AI 简报不计算总分/等级（决策 #13）。

### 3.1 全局交互规范（所有页面必须遵守）

| 项           | 规范                                                                                              |
| ----------- | ----------------------------------------------------------------------------------------------- |
| 页面容器        | 全屏页 `page`：头部=返回键（chev-l）+ 居中标题 + 右上动作（可选）；底部弹层 `sheet`：从底部滑出，点遮罩关闭                             |
| 底部 Sheet 规范 | 标题行 `stitle`；内容区可滚动；取消行为两种：面板内「取消」胶囊按钮（与主按钮并排等宽）或底部独立「取消」行（仅纯选择面板态使用）                           |
| 按钮组规范       | 双按钮并排：线框「取消」（flex:1）+ 主色「保存××」（flex:1\~2），间距 10px；禁止把保存和取消分离在页面两端                               |
| 表单头部        | 返回键 + 居中标题「宠物名 · 事项名」（如「小白 · 疫苗」）+ 右侧占位（不放保存）                                                   |
| 字段类型        | seg 胶囊单选 / text 文本 / num 步进器（− 数字 ＋）/ date 日期 / dateNext 自动推算日 / area 备注 / switch 开关 / chips 多选 |
| 必填校验        | 未满足必填 → toast 提示首个缺失字段，不跳转不标红                                                                   |
| toast       | 轻提示（如「已完成「体内驱虫」，自动记了一笔 🐾」），自动消失                                                                |
| 空状态         | 统一插画风：大 emoji + 主文案 + 引导副文案（如「还没有成长瞬间 / 点右下角相机，拍一张…」）                                           |
| 危险操作        | 删除类操作二次确认（confirm 弹窗，写明不可恢复）                                                                    |
| 左滑删除        | 红色删除块宽 72px、与卡片同高同圆角，完全藏于卡片后；滑出后点红块删除；点卡片（未滑开时）进入编辑                                             |
| 免责声明        | 所有 AI 结论页底部固定：「仅供参考，不替代专业兽医诊断」                                                                  |

| 分数 | 评级 | tip 文案 |
| --- | --- | --- |

| 3 | 偏瘦 | 能轻易摸到肋骨、覆肉偏薄，建议适当增加喂食与营养 |

| 6 | 偏胖 | 腰线变浅、覆肉较多，建议控制食量并增加运动 |

#### 7.4.2 链接邀请分享（正式版机制细化）
邀请生命周期：**生成 → 分享 → 打开落地页 → 接受入家庭**（或过期 / 撤回失效）。

| 环节    | 规则                                                                                                                 |
| ----- | ------------------------------------------------------------------------------------------------------------------ |
| 渠道三选一 | 微信分享卡片（转发好友/群）、复制链接（粘贴任意渠道）、二维码（面对面扫码）。原型 `data-way` 已含三种                                                          |

### 8.5 OCR 识别（双场景：① 病历/疫苗本 ② 狗证照片〔v2.37〕）

**场景 1：病历/疫苗本识别**（入口=「我的」体检报告上传+病历夹 FAB+记一笔辅助录入）

**场景 2：狗证照片识别（v2.37 新增，入口=狗证档案页录入表单〔7.5〕）**

### 12.1 全局空值兜底总则（v2.19 落稿：未填任何信息时的展示规则）

**原则**：任何信息未填 / 无数据时，页面**结构不塌陷、不报错、不留死链**，核心模块照常渲染。按「单字段空值」与「空列表」两类统一兜底，各页散落的空态文案（正文各节已分别落稿）均遵循以下总则：

| 类型                                  | 兜底规则                                                                                         |
| ----------------------------------- | -------------------------------------------------------------------------------------------- |
| 单行键值字段未填（登记证号 / 有效期 / 备注等）          | 统一显示占位符 **「—」**，灰色浅字，不挤压页面结构；不隐藏整行（用户知道「这里可以填」）                                              |
| 头部 chips / 摘要行未填（品种 / 年龄 / 体重 / 性别） | **缺项不渲染、不占位、不显示「—」**；有几项渲染几项，摘要用「·」直接合并                                                      |
| 空列表 / 零数据页（记录 / 待办 / 病历 / 相册等）      | 统一插画空态：大 emoji（默认 🐾，各页可定制）+ 主文案 + 引导副文案 + 引导按钮，按钮指向该页**第一个写操作入口**；文案按页面定制（不写「暂无数据」这类无引导性的话） |
| 新用户 / 新宠物（刚建档，零记录）                  | 空态文案与功能联动，引导完成第一个写操作（记一笔 / 建提醒）；不弹教程、不阻塞使用                                                   |

**核心场景案例（研发直接按此实现）**：

| 场景                | 未填任何信息时的展示                                                                                          |
| ----------------- | --------------------------------------------------------------------------------------------------- |
| 宠物页宠物信息卡摘要         | 未填品种 / 年龄 / 体重 → 缺项不占位直接合并，如「小白 · 猫咪 · 弟弟」；仅填建宠必填 4 项（名字 / 种类 / 性别 / 出生日期，4.3）即可完整渲染宠物页，其余字段之后在档案里补全 |
| 萌宠档案头部 chips      | 未填年龄 / 体重 → 对应 chip 不渲染，不显示「—」                                                                      |
| 萌宠档案健康卡           | 体重趋势无记录 → 大字「—」+ 折线不渲染；疫苗 / 驱虫无记录 → 「暂无提醒记录，点下方新建添加」                                                |
| 健康简报（8.2）        | 「今天还没有可以解读的数据 / 护理、吃饭、喝水、体重都不是必填项。先随手记一笔吃饭或喝水，简报就能开始读懂 TA 的状态。」+「去记第一笔」                             |
| 狗证档案·登记信息卡（7.5）  | 未录入 → 灰图标行「暂无登记信息 / 点右上角『编辑』开始录入」；名下无狗 → 引导空态「还没有狗狗档案 · 先添加一只狗狗，就能登记它的养犬证了」                         |
| 我的·资料卡（未授权，4.2.1） | 头像默认爪印占位 🐾；昵称兜底「宠友+手机号前 3 位」；不阻塞使用，设置页可重新授权同步                                                      |
